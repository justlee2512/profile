Richard LeImage Drive

Private image storage built for reliability.A multi-account Node.js application for uploading, organizing, sharing and downloading image libraries. Images, metadata, sessions and WebP thumbnails are stored directly in PostgreSQL.
Node.js 20+PostgreSQL BYTEADockerKubernetesGitHub ActionsArgo CD

How it works

From upload to storage

The application keeps the web layer stateless so traffic can reach any Kubernetes replica, while PostgreSQL remains the single source of truth for files and user sessions.

01

Upload and organize

Users upload images sequentially, move multiple items between folders and manage their private library.

02

Process images

The Node.js app validates each file and creates WebP thumbnails immediately or lazily on first view.

03

Store in PostgreSQL

Original images, thumbnails and metadata are persisted with BYTEA. Sessions are shared between all replicas.

04

Deliver securely

Cloudflare and NGINX Ingress route HTTPS traffic. Selected images can be downloaded together as a ZIP.

Multi-account access

Supports up to five isolated accounts with database-backed sessions and a 15-minute sliding idle timeout.

Kubernetes ready

Readiness and liveness probes, shared sessions and configurable connection pools support multiple replicas without sticky sessions.

Database protection

Upload/download concurrency limits reduce pressure on PostgreSQL and HDD storage while handling large image files.
